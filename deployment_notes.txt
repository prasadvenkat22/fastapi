=======================================
 Digital Ocean Deployment Guide
 FastAPI + PostgreSQL
=======================================

PREREQUISITES
- Digital Ocean account
- SSH key added to your DO account
- Anthropic API key from console.anthropic.com
- Voyage AI API key from dash.voyageai.com

=======================================
STEP 1: Create a Droplet
=======================================
- Go to Digital Ocean -> Create Droplet
- Image: Ubuntu 24.04
- Plan: Basic $12/mo (2GB RAM, 1 vCPU)
- Auth: SSH key (recommended)
- Note the IP address after creation

=======================================
STEP 2: SSH into the Droplet
=======================================
  ssh root@<YOUR_DROPLET_IP>

=======================================
STEP 3: Clone and Run Setup Script
=======================================
  cd /opt
  git clone https://github.com/prasadvenkat22/fastapi.git
  cd fastapi
  bash setup-server.sh

=======================================
STEP 4: Setup Script Prompts
=======================================
The script will ask for:

  Prompt                   What to Enter
  ----------------------   ------------------------------------------
  PostgreSQL password      Any strong password (creates the DB with it)
  pgAdmin password         Any password (only for debug mode)
  Anthropic API Key        Your key starting with sk-ant-...
  Voyage AI API Key        Your key starting with pa-...
  Domain                   Your domain, or press Enter to use the IP
  Start now?               y

IMPORTANT: Do NOT use quotes around any values.

=======================================
STEP 5: Verify Deployment
=======================================
  ./deploy.sh health

All 3 checks should show OK:
  - FastAPI: OK
  - PostgreSQL: OK

=======================================
STEP 6: Access Your App
=======================================
Via nginx (port 80) - RECOMMENDED:
  FastAPI docs:      http://<DROPLET_IP>/docs
  FastAPI API:       http://<DROPLET_IP>/api/
  FastAPI redoc:     http://<DROPLET_IP>/redoc

Direct access (by port):
  FastAPI docs:      http://<DROPLET_IP>:8000/docs

=======================================
NGINX ROUTING (port 80)
=======================================
Nginx acts as a reverse proxy on port 80:
  /              -> FastAPI (port 8000)
  /docs          -> FastAPI Swagger docs
  /redoc         -> FastAPI Redoc docs
  /openapi.json  -> FastAPI OpenAPI spec
  /api/*         -> FastAPI backend endpoints

=======================================
DEPLOY MANAGEMENT COMMANDS
=======================================
All commands run from /opt/fastapi on the server:

  ./deploy.sh start      Start all production services
  ./deploy.sh stop       Stop all services
  ./deploy.sh restart    Restart all services
  ./deploy.sh update     Pull latest code, rebuild, and restart
  ./deploy.sh logs       Show logs (follow mode)
  ./deploy.sh status     Show container status and memory usage
  ./deploy.sh stats      Show live resource usage
  ./deploy.sh health     Run health checks on all services
  ./deploy.sh debug      Start with pgAdmin enabled (port 5050)

=======================================
UPDATING CODE ON SERVER
=======================================
After pushing changes to GitHub:

  ssh root@<DROPLET_IP>
  cd /opt/fastapi
  ./deploy.sh update

If nginx shows 502 after update, do a full stop/start:
  ./deploy.sh stop
  ./deploy.sh start

=======================================
RUNNING LOCALLY
=======================================
Start all services:
  docker compose up -d --build

Stop all services:
  docker compose down

Access locally:
  FastAPI docs: http://localhost:8000/docs
  pgAdmin:      http://localhost:5050
  Nginx:        http://localhost (port 80)

=======================================
SERVICES & PORTS
=======================================
  Service       Port    Description
  ----------    -----   -------------------------
  Nginx         80      Reverse proxy (main entry)
  FastAPI       8000    REST API backend
  PostgreSQL    5432    Relational database
  pgAdmin       5050    DB admin (debug mode only)

=======================================
ENV FILE RULES
=======================================
- .env is for local development
- .env.production is for the server (generated by setup-server.sh)
- .env symlinks to .env.production on the server
- NEVER use quotes around values in either file
- NEVER commit .env or .env.production to git (they contain secrets)
- .env.production.example is the safe template checked into git

=======================================
USERS, ROLES AND PASSWORDS
=======================================
auth_notes.txt is the authoritative reference — roles, tokens, what
enforcement does and does not cover, and why users are created from a
script rather than the API. Only the commands are repeated here.

  ssh root@<DROPLET_IP>
  cd /opt/fastapi

  # create the account and give it a role (admin | trader | user)
  docker compose -f docker-compose.yml -f docker-compose.prod.yml       exec app python scripts/add_user.py someone@example.com admin

  # set their password -- NOTE: no -T, see troubleshooting below
  docker compose -f docker-compose.yml -f docker-compose.prod.yml       exec app python scripts/set_password.py someone@example.com

Re-run add_user.py with a different role to change it; the password is left
alone. Re-run set_password.py to change or reset a password — that is the
whole recovery story, there is no reset email.

The API is currently OPEN: /auth/login issues tokens but no route requires
one, and POST/DELETE /CRUD/users/ answer unauthenticated. Keep the host
behind a firewall until section 6 of auth_notes.txt is done.

=======================================
TROUBLESHOOTING
=======================================
Problem: "env file .env not found"
  Fix: ln -s .env.production .env

Problem: Container keeps restarting
  Fix: docker compose logs <service> --tail 50

Problem: Anthropic/Voyage API key error
  Fix: Edit .env.production, fix the ANTHROPIC_API_KEY / VOYAGE_API_KEY
       line (no quotes), then ./deploy.sh restart. Note: keys are only
       shown in full once at creation in each provider's console — if
       you copied from a masked list view, generate a fresh key instead.

Problem: Out of memory
  Fix: Use docker-compose.prod.yml (deploy.sh uses it automatically)
       which limits memory per container for 2GB droplets

Problem: nginx 502 Bad Gateway
  Fix: ./deploy.sh stop && ./deploy.sh start
       (full stop/start forces nginx to re-resolve DNS)

Problem: ModuleNotFoundError in Python
  Fix: Add the missing package to requirements.txt,
       push to GitHub, then ./deploy.sh update on server

Problem: "Warning: Password input may be echoed" when setting a password
  Fix: You used `docker compose exec -T`. The -T flag removes the TTY, so
       getpass cannot hide the typing and the password appears on screen
       and in your shell's scrollback. Drop the -T. If it already echoed,
       set a different password.

Problem: ModuleNotFoundError: No module named 'config' running a script
         in scripts/
  Fix: Already fixed -- add_user.py and set_password.py put the repo root
       on sys.path themselves. If you add a NEW script in scripts/, copy
       that bootstrap. Python puts the SCRIPT's directory on sys.path, not
       the working directory, so `python scripts/x.py` from /app cannot
       import config or models_pgdb. The cron job hides this by exporting
       PYTHONPATH=/app in its own invocation.

Problem: 401 "Incorrect email or password" for an account you know exists
  Fix: Usually no password has been set yet -- check with:
         docker exec postgres_container psql -U postgres -d postgres -c            "select email, password_hash is not null as has_pw from users;"
       Then run set_password.py. Login returns the SAME message for an
       unknown email, a wrong password, a disabled account and one with no
       password set, on purpose: distinguishing them would let anyone test
       which emails are registered. Also check the email case -- it is
       matched exactly and stored lowercase.
